# 模型池 - 2026-05-20 IJPay心智模型

## 6条心智模型

### M1 支付平台即配置+门面
支付集成的核心抽象模式：每个支付平台 = 配置对象(密钥/回调URL/证书) + API门面类(统一下单/退款/查询)。
配置与API调用分离，配置通过请求上下文传递。
**来源**: IJPay的XxxApiConfig + XxxApiConfigKit + XxxApi 三层模式
**适用**: 链客宝/数智港/任何需要多支付渠道的项目

### M2 统一签名体系分离于业务逻辑
签名/验签是支付集成的横切关注点，不应混入业务代码。通过PayKit/RsaKit统一门面处理。
**来源**: IJPay的PayKit + RsaKit 分层设计
**Python等价**: cryptography库的RSA/HMAC-SHA256/MD5封装

### M3 可替换HTTP委托模式
将HTTP客户端抽象为接口，底层实现可随时替换（Java: HuTool↔OkHttp, Python: httpx↔aiohttp）
**来源**: IJPay的AbstractHttpDelegate + HttpKit.setDelegate()
**Python等价**: ABC + 全局委托切换

### M4 枚举驱动API路由
将所有API端点定义为枚举，URL构建集中治理。新增/修改端点不涉及字符串拼接，降低出错率。
**来源**: IJPay的WxApiEnum + 30+个枚举分类
**Python等价**: Python Enum + 统一URL构建器

### M5 多层证书自动轮换
微信v3核心机制：从平台证书API获取→AES-GCM解密→X509解析→有效期检查→自动轮换的全链条
**来源**: IJPay-WxPay v3 API + AesUtil + PayKit
**Python等价**: apscheduler定时任务 + cryptography证书解析

### M6 支付回调双重验证
异步通知先验签名(防篡改)，再验业务参数(退款金额/订单号)，双重验证防止重放攻击
**来源**: IJPay的XxxPayController抽象模板
