> **项目**: AI数智名片 (AI Digital Business Card)
> **文档编号**: SEC-DATA-CLASS-001
> **版本**: v1.0(初稿)
> **创建日期**: 2026-08-06
> **状态**: 初稿待评审

> **适用范围**: 所有由 AI数智名片 系统存储、处理、传输的数据

## 1. 分类体系总览

本体系定义 **4 级数据分类标签**,所有数据资产在创建时必须标注分级标签,并在存储、传输、展示、备份、销毁各生命周期阶段按对应要求执行保护措施。

| 级别 | 标签 | 颜色 | 定义 | 示例数据 |
|------|------|------|------|----------|
| **C1** | 🔓 **公开** | 绿色 | 可向公众完全公开,泄露无影响 | 名片展示信息、公开API文档、产品介绍、健康检查状态 |
| **C2** | 🔐 **内部** | 蓝色 | 仅限内部员工/已认证用户访问,泄露影响轻微 | 访客统计、非PII业务统计、内部API文档、团队名称 |
| **C3** | 🛡️ **机密** | 黄色 | 含个人身份信息(PII),泄露可能造成中等影响或法律风险 | 手机号、邮箱、订单信息、名片内容、匹配记录 |
| **C4** | ⛔ **限制** | 红色 | 泄露将造成严重/不可逆后果,受法规强约束 | 支付密钥、用户密码哈希、JWT密钥、数据库连接串 |

### 1.1 与既有分级文档的映射

项目已有 `backend/app/docs/security/data-classification.md`(L1-L4 四级:公开/内部/敏感/机密),本文件为 SOC 2 落地口径,两者映射关系如下,后续代码中的分类标记以本文件为准:

| 本文件 | 既有文档 | 说明 |
|--------|----------|------|
| C1 公开 | L1 公开 | 一致 |
| C2 内部 | L2 内部 | 一致 |
| C3 机密 | L3 敏感 | 合并原 L3,并吸收原 L4 中的用户联系方式(手机号/邮箱/订单) |
| C4 限制 | L4 机密(部分) | 仅保留密钥类、凭据类、哈希类数据 |

## 2. 各级别详细要求

### 2.1 C1 公开(名片展示信息等)

| 维度 | 要求 |
|------|------|
| **定义** | 向公众完全公开的信息,泄露/篡改无安全影响 |
| **示例数据** | 名片展示信息(姓名/公司/职位/头像等用户主动公开内容)、公开 API 文档(`/docs`)、产品介绍页、`/health` 健康检查 |
| **存储位置** | 数据库 `users`/`brochures` 表明文列;对象存储(头像/媒体 URL);Nginx 静态资源 |
| **加密要求** | 存储:无需加密;传输:建议 TLS(HTTPS 已全局强制,无额外要求) |
| **访问权限** | 无需认证,任何人可访问;允许 CDN/浏览器缓存 |
| **保留期限** | 永久(合规要求除外);无需审计 |

### 2.2 C2 内部(访客统计等)

| 维度 | 要求 |
|------|------|
| **定义** | 仅限内部员工或已认证用户访问,泄露影响轻微 |
| **示例数据** | 访客统计(浏览量/访客数/来源分布)、非PII业务统计、内部API文档、团队名称/结构、订单号(不含明细) |
| **存储位置** | 数据库业务表(visitor 统计表、analytics 聚合表);Prometheus 指标库 |
| **加密要求** | 存储:明文可接受,推荐数据库 ACL;传输:必须 TLS 1.2+ |
| **访问权限** | 需要认证;建议 RBAC 限制读写;禁止 CDN 缓存,内部缓存 TTL ≤ 300s |
| **保留期限** | 业务需要 + 最长 7 年(税务/法律);关键写操作审计 |

### 2.3 C3 机密(手机号/邮箱/订单等)

| 维度 | 要求 |
|------|------|
| **定义** | 含个人身份信息(PII),泄露可能对用户或业务造成中等影响,受《个人信息保护法》约束 |
| **示例数据** | 手机号、邮箱、订单信息(金额/交易号)、名片内容、匹配记录、访客 IP、访客留言、OCR/爬虫提取的联系方式 |
| **存储位置** | 数据库 `users.phone`、`users.email`、`payment` 表、`imported_contacts` 表(phone_hash/phone_enc/phone_last4)、`unified_profiles` 表 |
| **加密要求** | 存储:推荐 AES-256 加密(明文存储的 PII 字段按 C4 处理);传输:必须 TLS 1.2+;备份:加密 |
| **访问权限** | RBAC + 数据级权限(仅本人或管理员);输出默认脱敏(如 `138****0000`);禁止缓存(no-store);所有访问审计 |
| **保留期限** | 业务结束后 ≤ 90 天(匿名化或删除);日志输出必须脱敏 |

### 2.4 C4 限制(支付密钥/密码哈希等)

| 维度 | 要求 |
|------|------|
| **定义** | 凭据类/密钥类数据,泄露将造成严重安全后果或不可逆损害,受强法规约束 |
| **示例数据** | 支付密钥(支付宝私钥/微信密钥)、用户密码哈希(password_hash)、JWT_SECRET、数据库连接串(DATABASE_URL)、第三方 API Key、wechat_openid 明文 |
| **存储位置** | 环境变量 `.env.production`(部署服务器,禁止入库);数据库 `users.password_hash` 列(bcrypt 哈希);密钥管理服务(KMS/HSM) |
| **加密要求** | 存储:必须加密(AES-256-GCM),独立密钥,密钥轮换 ≤ 90 天;传输:必须 TLS 1.3(TLS 1.2 最低接受);备份:加密 + 独立密钥 |
| **访问权限** | 最小权限原则:仅极少数管理员可访问,启用 MFA;禁止任何形式缓存;每次访问必须审计(含失败尝试);严禁明文写入日志 |
| **保留期限** | 最短业务需要,到期立即安全删除(不可恢复) |

## 3. 数据生命周期控制矩阵

| 阶段 | C1 公开 | C2 内部 | C3 机密 | C4 限制 |
|------|---------|---------|---------|---------|
| **采集** | 无需同意 | 明确目的告知 | 用户明确同意 | 单独明示同意 |
| **存储** | 明文 | 明文/ACL | AES-256 加密 | AES-256-GCM + 独立密钥 |
| **传输** | HTTP 可接受 | TLS 1.2+ | TLS 1.2+ | TLS 1.3 |
| **展示** | 明文 | 明文(内部) | 脱敏(默认) | 禁止展示 |
| **备份** | 明文 | 加密 | 加密 | 加密 + 独立密钥 |
| **销毁** | 常规删除 | 安全擦除 | 安全擦除 | 不可恢复销毁 |
| **审计** | 不审计 | CREATE/UPDATE/DELETE | 所有 CRUD | 每次访问 |

## 4. 角色访问矩阵

| 角色 | C1 公开 | C2 内部 | C3 机密 | C4 限制 |
|------|---------|---------|---------|---------|
| 未认证用户 | ✅ | ❌ | ❌ | ❌ |
| 普通用户 (user) | ✅ | ✅ 本人数据 | ✅ 本人数据(脱敏) | ❌ |
| 企业用户 (enterprise) | ✅ | ✅ 本团队数据 | ✅ 本团队数据(脱敏) | ❌ |
| 管理员 (admin) | ✅ | ✅ 全部 | ✅ 全部(脱敏) | ⚠️ 仅必要场景 |
| 超级管理员 (superadmin) | ✅ | ✅ 全部 | ✅ 全部(脱敏) | ✅ 最小权限(MFA) |
| 审计员 (auditor) | ✅ | ✅ 只读 | ✅ 只读(日志) | ✅ 只读(审计日志) |

## 5. 脱敏规则速查(与脱敏审计联动)

| 数据类型 | 脱敏规则 | 示例 |
|----------|----------|------|
| 手机号 | 前3后4,中间 `*` | `138****0000` |
| 姓名 | 保留姓氏,名字 `*` | `张*` |
| 邮箱 | 用户名前2位 + `***` + 域名 | `te***@example.com` |
| IP | 保留前3段 | `192.168.1.*` |
| 微信 openid | 完全隐藏 | `********` |

> 脱敏覆盖缺口详见 `docs/security/masking_gap_report.md`。

## 6. 违规处理

| 违规行为 | 处理措施 |
|----------|----------|
| 开发环境使用含 C3/C4 的生产数据 | 立即停止,报告 CISO,安全擦除 |
| 将 C4 数据明文写入日志 | 立即修复,清理日志,事件调查 |
| 未授权访问 C3/C4 数据 | 安全事件上报,收回权限,纪律处分 |
| 未脱敏展示 C3 数据 | 紧急修复,数据泄露评估 |

## 7. 复审与维护

| 级别 | 复审频率 | 触发条件 |
|------|----------|----------|
| C1 公开 | 每年 | 业务重大变更 |
| C2 内部 | 每年 | 团队/业务变更 |
| C3 机密 | 每半年 | 新功能上线,法规更新 |
| C4 限制 | 每季度 | 密钥轮换,安全事件后立即 |
